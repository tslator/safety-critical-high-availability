# D-2026-09-17-003: T1.3 CRC Integrity Design Analysis

- Date: 2026-09-17
- Status: Accepted
- Related decision: [DEC-0005](../decisions/0005-t1.3-crc-integrity.md)
- Authorizes: Phase 1 task T1.3 in [docs/phases/PHASE_1_SHARED_MEMORY.md](../phases/PHASE_1_SHARED_MEMORY.md)

## Question

How should T1.3 (CRC integrity and corruption detection) be designed on top of
the merged T1.2 protocol, so that the per-slot CRC, the corruption-skip path,
and the region `integrity_word` all fit the existing layout discipline,
hot-path rules, and verification scope without weakening any Tier 1 property?

## Context

G1.2 is complete (local six-config matrix plus hosted CI run 35214976207 on
commit 95f9506). The T1.2 protocol uses per-slot ready/commit sequence markers
with exclusive ownership between claim and release; `verify_consistent()`
cross-checks every slot counter against the stored head/tail window under a
documented quiescence precondition, with one-way (spurious-false-only) failure
direction. T1.3 must add per-slot CRC-32C, a corruption path in `try_pop`, a
corruption counter, and the whole-region integrity word — while keeping the
hot path allocation-free, syscall-free, exception-free, and mutex-free
(`POLICIES.md` mandatory; `ARCHITECTURE_RULES.md` hot-path boundary).

## Findings

### 1. Slot layout: CRC inside the cell, payload shrinks 56 → 52, version bump

The plan sketch stores `crc` in the slot. To keep every `Cell` at exactly one
64-byte cache line (the T1.1/T1.2 discipline, witnessed by
`static_assert(sizeof(LockFreeRingBuffer<2, kDefaultSlotBytes>::Cell) == 64)`),
the cell becomes `{ sequence: u64, payload[52], crc: u32 }`. "The CRC lives in
the slot" means it is a **member of `Cell`** — physically inside the slot's own
cache line of `cells_[]` — not stored elsewhere (no parallel side array after
`cells_`, no per-ring word in `RingBufferHeader`):

```text
v2 (G1.2):                          v3 (T1.3, accepted):
  [0..8)   sequence  atomic u64        [0..8)   sequence  atomic u64   unchanged
  [8..64)  payload[56]                  [8..60)  payload[52]                -4 bytes
                                       [60..64) crc         u32             NEW, in-cell
```

In-cell placement is what makes the per-slot check self-contained (slot *i* is
judged from cell *i* alone), keeps the tag inside the same exclusive-ownership
window as the payload it authenticates (finding 3), and adds no layout surface
beyond 4 bytes in an existing line:

- `kDefaultSlotBytes` changes 56 → 52 (payload bytes only, same semantics as
  today; `RingBufferHeader::slot_bytes` will record 52).
- Field order keeps `sequence` at offset 0, so all existing direct counter
  access in tests and verification stays valid.
- `sizeof(SharedRegion)` is unchanged (~200 KiB): cells stay one line each.
- This is a slot-format change: per the Layout Versioning rule in
  `ARCHITECTURE_RULES.md`, `kRegionVersion` must be bumped 2 → 3 with a version
  history note. v2 is already merged (b4dd249, G1.2 green on hosted CI), so a
  silent relayout of v2 storage is not acceptable; the bump is cheap now
  because T1.4 (attach) has not landed and nothing persists regions yet.

Alternatives rejected: growing the cell to 128 B to keep a 56-byte payload
(two cache lines per slot, more bytes touched per operation, worse false-
sharing story); moving the CRC into `RingBufferHeader` (not per-slot; the
header is static after init and cannot cover individual slots).

### 2. CRC-32C: SSE4.2 intrinsics where compiled in, compile-time table otherwise

CRC-32C (Castagnoli, reflected; poly 0x1EDC6F41, reflected table constant
0x82F63B78; init and xorout `0xFFFFFFFF`) — the standard iSCSI/RoCE variant.

- Public API in `integrity.hpp`/`src/integrity.cpp`: `crc32c(data, len)` plus
  `crc32c_init/update/finalize` running form (the region integrity word needs
  to hash a header block and a separate seq word in one chain).
- Implementation: per-byte `_mm_crc32_u8` chain under
  `#if defined(__SSE4_2__)`; otherwise a 256-entry table built at compile time
  (constexpr — zero runtime allocation, satisfies the hot-path rules). The two
  paths share the init/update/finalize structure and must be bit-identical.
- All current toolchains in this repo build with the x86-64 baseline (host
  GCC 13.3.0, container GNU 12.2.0, CI): none enables SSE4.2, so every gated
  build exercises the table path; the intrinsic path activates automatically
  under `-march`/`-msse4.2` builds without any CMake option. No new CMake
  options are introduced (keeps T1.5's "none expected" README note true).
- **Resolution (accepted 2026-09-17):** keep both paths, following the plan's
  "hardware intrinsics where available, table fallback" guidance verbatim — no
  deviation from the plan wording.

Known check values for tests: `crc32c("") = 0x00000000`,
`crc32c("123456789") = 0xE3069283` (verified at analysis time by an independent bitwise non-table Castagnoli
implementation), plus fixed 52-byte full-payload-field patterns
(`0x00 x 52 -> 0x6B668ACA`, `0x00..0x33 -> 0xBCF4EC70`) whose expected values
were cross-checked against that same independent reference.

Residual risk (accepted): the intrinsic path is only exercised in SSE4.2
builds, which no gate config compiles today. It is a single per-byte loop with
identical init/xorout structure; a CI leg with `-msse4.2` can be added later if
desired. The table path is what all shipped configurations run.

### 3. CRC scope and commit-path write ordering

- The producer computes the CRC under exclusive ownership (between its
  successful `tail_` CAS and the commit store), over the **full** `SlotBytes`
  payload field — not just `sizeof(T)`. It is stored as a plain (non-atomic)
  `uint32_t` immediately before the release-store of `sequence`, so its
  visibility follows the exact same release/acquire edge that already publishes
  the payload. This drops the plan sketch's `std::atomic<uint32_t> crc`:
  there is no concurrent access outside the ownership window, and a plain
  store avoids an extra RMW per commit.
- `try_push` does not zero payload bytes beyond `sizeof(T)`; because the CRC
  covers the entire field, stale tail bytes are still verified (any bit flip
  anywhere in the slot is detected). Recorded deliberately: canonical
  zero-fill would cost an extra store per push for no detection gain.
- The consumer recomputes over the same full field after its `head_` CAS claim;
  it already holds exclusive ownership, so plain reads of payload and stored
  crc are race-free under TSan/UBSan (the existing memcpy argument extended to
  one more read).

### 4. Corruption path in `try_pop`: skip, count, never copy out

On a claimed slot whose CRC mismatch is detected:

1. Release the slot by storing `ready(p + n)` — exactly the marker a normal
   pop stores. The protocol state stays valid: the position is consumed, the
   slot re-arms for the next lap, and `verify_consistent()` still holds after
   quiescence (a skipped slot is indistinguishable from a popped one at the
   counter level).
2. Increment a per-ring atomic corruption counter — a new 64-byte-aligned word
   in `LockFreeRingBuffer` (consumer-side; producers never write it, so no new
   false sharing). Zeroed by `initialize()`. Ring size grows one cache line.
3. Return `false` without touching the out parameter: the consumer must never
   copy a corrupted payload (plan T1.3 step 2).

Semantics pinned for callers: `try_pop` returning `false` means "no value
delivered on this call" (same as empty); what happened is observable via
`corruption_count()`. Each corrupted position is counted exactly once because
ownership at claim time makes the release single-shot. Corrupted messages are
lost by design — detection and accounting, not recovery (plan S3: "CRC
mismatch detected; corrupted slot skipped; alert logged"). The counter is
observability-only: no protocol decision branches on it.

### 5. Region `integrity_word`: what it covers and how the commit path updates it

**Definition.** `integrity_word = crc32c( ring_buffers[0..kMaxWorkers) raw
(192 B) ‖ global_seq (8 B) )`. Identity is deliberately excluded:
`verify_identity()` already compares the identity words against compiled-in
constants, which is strictly stronger than a CRC for those bytes; keeping the
hash to "per-worker header state and global_seq" matches plan step 1 exactly.

**Why a region-level commit wrapper.** The lock-free core must stay standalone
(tests drive stack-allocated rings with no region). T1.3 therefore adds a
region-level commit API in `shared_region.{hpp,cpp}`:

```cpp
// Region-level commit path (T1.3): publishes on worker idx's ring and, on
// success, advances global_seq and refreshes integrity_word.
template <typename T>
bool push(SharedRegion& region, std::size_t worker_idx, const T& value);
```

`push` = `region.rings[idx].try_push(value)` + (on success) a `global_seq`
`fetch_add` and an `integrity_word` refresh. Raw `rings[i].try_push` remains
available but bypasses region accounting (documented; low-level/test use).
Phase 2 workers attach to a region, so the wrapper is also their natural API.

**Refresh with quiescent convergence.** Naive "fetch_add, then read seq after
the add and store `H(headers, seq_read)`" does **not** converge: under relaxed
ordering two committers can invert their stores (A adds 5→6 and reads 6; B
adds 6→7 and stores H(7); A then stores H(6)), leaving a stale word even after
quiescence. The accepted scheme is a small CAS loop per commit:

```text
loop:
    W0 = integrity_word.load(relaxed)
    S  = global_seq.load(relaxed)
    E  = crc32c(headers ‖ S)
    if (W0 == E) break                 // already consistent
    if (integrity_word.CAS(W0 → E)) break   // publish H(S)
```

At quiescence every in-flight updater reads `S = F` (the final seq, no adds
remain) and stores exactly `H(F)` — an idempotent value — so the last store
always leaves the word consistent; live traffic can still show transient
inconsistency. Cost: one extra load + one non-contended CAS per commit at this
project's scale (3 workers), against a 200-byte CRC-32C compute.

**Observer contract (Phase 4).** A single snapshot gives a corruption check:
recompute `H` from the observed headers and `global_seq`, compare with the
stored word; mismatch ⇒ suspect header/seq corruption (a coincidental match on
corrupted input has probability ≈ 2⁻³²). Staleness — a writer that stopped
committing — is detected as *no change* across successive samples (the plan §8
"periodic health checksum"), not by one snapshot. Quiescence discipline mirrors
`verify_consistent()`: during live traffic a mismatch may be spurious; treat a
single mismatch as "unverified" and re-check under established quiescence. The
per-slot CRC remains the exact integrity gate; `integrity_word` is an
observability/staleness signal, never the safety boundary.

### 6. Test plan (new module `shared-memory/tests/integrity_test.cpp`)

Registered in `tests/CMakeLists.txt`; deterministic/small style per existing
suites:

- **Crc32cKnownVectors** — empty and `"123456789"` → `0xE3069283`, plus the
  fixed multi-byte pattern from finding 2; differential assertion
  `crc32c == table path` active whenever the test TU compiles with `__SSE4_2__`.
- **RingBufferCorruption** — push N deterministic messages through a small ring;
  flip payload bytes in one committed slot via `slots()`; the pop at that
  position returns `false`, `corruption_count() == 1`, all other messages intact
  and in order. Also: corruption of the stored CRC field itself is detected;
  corrupting all remaining slots drains cleanly (repeated `false` until empty,
  count exact, no UB) and later laps still work (skipped slots re-arm); a fresh
  ring's `corruption_count()` is zero after `initialize()`.
- **RegionIntegrity** — after `initialize`, stored word equals
  `compute_region_integrity(region)`; flipping one header byte makes the
  recomputed value disagree; `push` advances `global_seq` and the word, and a
  deterministic multi-worker (barrier-synchronized) mixed-traffic run ends
  quiescent-consistent, exercising the CAS-loop convergence of finding 5.

- `POLICIES.md` makes that a floor, not a ceiling, for shared-memory changes:

  under `setarch --addr-no-randomize`, see NOTES.md) must be green before T1.3

- Evidence recorded as a G1.3 section in `NOTES.md`; `docs/STATUS.md` moves to

  (Layout Versioning rule). On landing, two new deviation entries are appended
  to the Phase 1 plan: #9 (per-slot CRC field; payload 56 → 52; version 2 → 3)
  and #10 (`integrity_word` refreshed by a region-level commit wrapper with CAS
  convergence, not inside `try_push`).

## Alternatives Considered (summary)

- **CRC in the header, not the slot** — rejected: plan requires per-slot
  coverage; headers are static after init.
- **128-byte cells keeping a 56-byte payload** — rejected: two cache lines per
  slot, more bytes per operation, no benefit (52 B still fits demo messages).
- **`std::atomic<uint32_t>` crc as in the plan sketch** — rejected: plain store
  under exclusive ownership is sufficient and cheaper; the sequence
  release/acquire edge already orders it.
- **Region words updated inside `try_push` via injected pointers** — rejected:
  couples the standalone ring core to a region, breaks stack-allocated test
  storage, and pays per-push even when accounting is unneeded.
- **Read-after-add integrity refresh (no CAS)** — rejected: provably leaves a
  stale word at quiescence under store-order inversion (finding 5).

## Residual Risks

1. SSE4.2 intrinsic path not exercised by any current gate config (accepted and
   kept deliberately per plan wording — finding 2 resolution); the table path
   is what every shipped configuration runs.
2. `integrity_word` mismatches during live traffic are expected and one-way
   (spurious, never masking corruption); callers must follow the documented
   quiescence rule (finding 5). This is deliberately *not* mitigated by making
   the word race-free to read mid-traffic: that would require stronger ordering
   on the commit path for an observability signal.
3. Corrupted slots are consumed and lost, counted, unrecoverable — per plan S3;
  recovery semantics (if ever needed) belong to Phase 4 and must not be
  back-projected into the pop path.
