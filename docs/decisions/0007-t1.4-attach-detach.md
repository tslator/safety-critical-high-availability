# DEC-0007: T1.4 Shared Memory Attach/Detach Design

- Status: Accepted
- Date: 2026-09-18
- Related discussion: plan-mode design review (this task); canonical narrative in
  [Phase 1 plan T1.4](../phases/PHASE_1_SHARED_MEMORY.md)
- Authorizes: [T-0005](../tasks/T-0005-t1.4-attach-detach.md) (Phase 1 `T1.4`;
  gate G1.4 in [docs/phases/PHASE_1_SHARED_MEMORY.md](../phases/PHASE_1_SHARED_MEMORY.md))

## Context

T1.4 adds named `/dev/shm` attach/detach to `safety_crit::shared_memory`. The
region layout, flags, ring protocol, and CRC integrity already exist (T1.1-T1.3,
layout v3). T1.4 introduces **no new region fields**, so the layout stays at
`kRegionVersion == 3` and no version bump is needed (the Layout Versioning rule
in `ARCHITECTURE_RULES.md` only fires on layout/metadata/slot-format changes).

Two constraints constrain the shape of the API:

- The project standard is **C++20**; `std::expected` (C++23) is not permitted in
  production code (PHASE_0_CONTAINER_AND_TOOLING.md), and the attach path must
  not throw. The deliverable wording is "explicit error codes
  (`std::expected`-style pair), no exceptions".
- Attach/detach is **outside the hot path** (Hot-Path Boundary in
  `ARCHITECTURE_RULES.md`), so `mmap`/`ftruncate`/`errno`/errno-mapping are
  permitted here.

The plan sketch's `shared_region.hpp` did not anticipate that the attach API
pulls POSIX headers (`<sys/mman.h>`, `<fcntl.h>`, `<unistd.h>`) into the
core layout header, which is included by every consumer.

## Decision

1. **The attach API lives in a dedicated header, `shm_attach.hpp`
   (+ `src/shm_attach.cpp`), not `shared_region.hpp`.** This keeps the widely
   included layout header free of POSIX dependencies; only code that attaches
   to named objects pays for the system headers. This is a deliberate deviation
   from the plan's deliverable file list and is recorded as such in the Phase 1
   plan. `shm_attach.hpp` includes `shared_region.hpp` (it needs the frozen
   layout) but not vice versa.

2. **No-exception error model: a value-or-error handle ("expected-style").**
   `AttachError` is an `enum class`, one enumerator per failure mode, with a
   `to_string`. The factory returns a `SharedRegionHandle` **by value** (it is
   move-only); the handle is either valid (holds the mapping) or invalid and
   carries the failure: `ok()`, `error()`, and `errnum()` (the originating
   `errno` on OS failures, `0` otherwise). This is the same shape as
   `std::expected<Handle, AttachError>` — a value or an error, discriminated
   explicitly, never a thrown exception — without needing C++23. Returning the
   handle by value (rather than a detached raw-pointer result struct) is
   required so the mapping's ownership is unambiguous: the handle that carries
   the error carries nothing to unmap; the handle that carries the region owns
   it and munmaps it on destruction. `std::expected` is forbidden (C++20);
   vendoring `expected-lite` was rejected for now to avoid a third-party
   dependency in this phase — if Phase 5's perturbation engine (plan §5b) needs
   the same shape broadly, introducing a shared polyfill is a decision then.

3. **Create-vs-existing detection via `O_CREAT` + `fstat` size, then identity.**
   `create_or_open(name)` opens `shm_open(name, O_RDWR | O_CREAT)`, `fstat`s
   the object, and branches on its size:
   - size `0` ⇒ this is a fresh object: `ftruncate` to exactly
     `sizeof(SharedRegion)`, `mmap`, `madvise`, then `initialize()` in place
     (which stamps identity).
   - size `== sizeof(SharedRegion)` ⇒ existing: `mmap`, then `verify_identity()`;
     **never** re-`initialize()` (that would reset a live region's rings).
   - any other nonzero size ⇒ reject with `kSizeMismatch` (foreign/stale object).

   Linux `/dev/shm` (tmpfs) provides zero-filled pages, so an object created by
   another path but not yet initialized, or one whose header was clobbered,
   reads `magic == 0` and fails `verify_identity()` with `kStaleIdentity`. Magic
   and version are checked against compiled-in constants (strictly stronger
   than a CRC, per DEC-0005 #5). `verify_identity()` is quiescence-independent,
   so attach against a region with live workers cannot be spuriously rejected by
   ring traffic; whole-ring `verify()` is still reserved for quiescent
   re-attachment of a specific victim (Phase 2/4 flow).

4. **`SharedRegionHandle` is RAII and move-only, created only via the static
   factory.** Constructors cannot fail without exceptions, so construction is
   funneled through `create_or_open` returning `AttachResult`. The destructor
   (and `detach()`) `munmap`s the mapping and closes the fd — and **never**
   `shm_unlink`s, because peers may still be attached and unlinking would
   destroy the object out from under them (a truncated/removed region is exactly
   the corruption the plan forbids).

5. **Destructive teardown is test-only.** `destroy(name)` performs
   `shm_unlink(name)` and exists solely to exercise re-attachment / stale
   rejection in tests (and, later, perturbation scenario S6). It is documented
   as never-for-production; nothing on the normal attach/detach path calls it.

6. **`madvise`: `MADV_DONTFORK` always, `MADV_HUGEPAGE` best-effort.**
   `MADV_DONTFORK` keeps the region out of forked children's address space
   (the supervisor forks workers; a child inheriting a stale mapping is a
   hazard). Consequence: a forked child that needs the region must re-attach by
   name (`create_or_open`) rather than inherit — this is exactly the
   re-attachment path T1.4 tests, and the Phase 2 handoff pattern. `MADV_HUGEPAGE`
   is optional: attempted only when the region is at least one hugepage, and its
   failure is **not** an attach failure.

## Consequences

- New files: `include/safety_crit/shared_memory/shm_attach.hpp`,
  `src/shm_attach.cpp`, test module `shm_attach_test.cpp`. `shm_attach.cpp` is
  added to the `safety_crit_shared_memory` sources; the test links the library
  and uses the standard `safety_crit_register_tests` wiring.
- `shm_open` lives in libc on glibc >= 2.34 (dev host 2.39, container Bookworm
  2.36); no `-lrt` link is added.
- The CTest suite name is lowercase `shm_attach` (Catch2 tag `[shm_attach]`) so
  the G1.4 gate command `ctest -R shm` matches the registered test names
  (`gtest_discover_tests` registers `<Suite>.<Name>`, and `-R` is case-sensitive).
- No layout or region-version change; region size stays ~193 KiB.
- A region is only safe to attach *after* its creator finished `initialize()`;
  attach does not block-wait for a concurrent creator. In the plan's flow the
  supervisor creates+initializes before spawning workers, so peers always see a
  fully initialized identity. The zero-fill ⇒ `magic==0` ⇒ `kStaleIdentity`
  behavior means a peer that races the creator rejects rather than misuses the
  region; retry-on-`kStaleIdentity` (if ever needed) is a Phase 2 concern.
- Deviation entry for the dedicated header is appended to the Phase 1 plan at
  landing, alongside the G1.4 gate evidence in `NOTES.md`.
