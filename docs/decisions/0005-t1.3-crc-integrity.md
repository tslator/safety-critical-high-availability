# DEC-0005: T1.3 CRC Integrity Design

- Status: Accepted
- Date: 2026-09-17
- Related discussion: [D-2026-09-17-003](../reviews/2026-09-17-t1.3-crc-integrity.md)
- Authorizes: [T-0004](../tasks/T-0004-t1.3-crc-integrity.md) (Phase 1 `T1.3`; gate in [docs/phases/PHASE_1_SHARED_MEMORY.md](../phases/PHASE_1_SHARED_MEMORY.md))

## Context

T1.3 adds CRC integrity and corruption detection to the `safety_crit::shared_memory`
library on top of the merged T1.2 protocol (G1.2 complete). The plan sketch's
slot layout, `try_pop` CRC path, and `integrity_word` declaration needed
concrete resolution against the implemented T1.2 cell/protocol design and the
hot-path and layout-versioning rules. See the linked discussion record for the
full findings, alternatives considered, and residual risks.

## Decision

1. **Per-slot CRC lives inside the cell.** `Cell` becomes
   `{ sequence: u64 @0, payload[52] @8, crc: u32 @60 }`: `kDefaultSlotBytes`
   shrinks 56 → 52 so each cell stays exactly one 64-byte cache line, and the
   CRC field sits at the end of the same slot it authenticates (no side array,
   no header word). This is a slot-format change: `kRegionVersion` bumps
   2 → 3 per the Layout Versioning rule in `ARCHITECTURE_RULES.md`.

2. **CRC-32C with both implementation paths, per plan wording.** CRC-32C
   (Castagnoli, reflected; init/xorout `0xFFFFFFFF`) implemented as an SSE4.2
   `_mm_crc32_u8` chain when the translation unit is compiled with
   `__SSE4_2__`, and a compile-time-generated 256-entry table otherwise
   (constexpr — no runtime allocation). The plan's "hardware intrinsics where
   available, table fallback" guidance is followed verbatim; no CMake option.
   An explicit `crc32c_table()` exposes the table path for differential
   testing. Known vectors are pinned in tests, including the published
   canonical value `crc32c("123456789") = 0xE3069283` and 52-byte
   full-payload-field patterns cross-checked against an independent bitwise
   reference at analysis time.

3. **Plain (non-atomic) CRC field, written under exclusive ownership.** The
   producer computes the CRC over the full payload field after writing the
   value and stores it as a plain `uint32_t` immediately before the commit
   release-store of `sequence`; visibility follows the same release/acquire
   edge as the payload. The plan sketch's `std::atomic<uint32_t> crc` is not
   used: no thread may touch a cell's bytes outside the claim/release window,
   and a plain store avoids an extra RMW per commit. `try_push` does not zero
   payload bytes beyond `sizeof(T)`; the full-field coverage still verifies
   them.

4. **Corruption path in `try_pop`: skip, count, never copy out.** On a claimed
   slot whose stored CRC mismatches the recomputation over the full payload
   field: release the slot with the same `ready(p + n)` marker a clean pop
   stores (protocol state and `verify_consistent()` stay valid), increment a
   per-ring atomic corruption counter on its own cache line (consumer-side;
   zeroed by `initialize()`), and return `false` without touching the out
   parameter. `false` means "no value delivered on this call" (same as
   empty); what happened is observable via `corruption_count()`, which is
   observability-only — no protocol decision branches on it. Corrupted
   messages are lost by design (plan S3: detection and accounting, not
   recovery).

5. **Region integrity word refreshed by a region-level commit wrapper.**
   `integrity_word = crc32c(ring_buffers[0..kMaxWorkers) ‖ global_seq)`;
   identity is excluded because `verify_identity()` already checks those words
   against compiled-in constants (strictly stronger than a CRC for them). The
   lock-free ring core stays standalone: the new region-level API
   `push(region, worker_idx, value)` performs the ring commit and, on success,
   advances `global_seq` and refreshes `integrity_word` via a CAS loop that
   re-reads the seq each iteration — stores are monotone in the hashed seq and
   converge to a consistent word at quiescence (the naive read-after-add store
   was rejected: it can leave a stale word after store-order inversion).
   Raw `rings[i].try_push` bypasses region accounting (documented; low-level/
   test use). Observer contract mirrors `verify_consistent()`: during live
   traffic a mismatch may be spurious (one-way failure direction); treat a
   single mismatch as "unverified" and re-check under established quiescence.

## Consequences

- Slot format and region version change (v2 → v3) before T1.4 lands, so no
  persisted or attached state exists that the bump breaks.
- New files: `integrity.hpp` / `src/integrity.cpp`, test module
  `integrity_test.cpp`; `LockFreeRingBuffer` grows one cache line (corruption
  counter) per ring; region size stays ~193 KiB, far below the 64 MiB
  `/dev/shm` mount.
- Deviation entries #9 and #10 are appended to the Phase 1 plan record at
  landing, alongside the G1.3 gate evidence in `NOTES.md`.
