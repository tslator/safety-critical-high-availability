## Scope

Implement named `/dev/shm` attach/detach for a `SharedRegion` with re-attachment
support and stale-object rejection.

## Deliverables

- `shm_attach.hpp` create-or-open attach API (dedicated header, not
  `shared_region.hpp` — see DEC-0007): exact compiled-in region size,
  `mmap` + `madvise` (`MADV_DONTFORK`, optional `MADV_HUGEPAGE`), in-place
  `initialize`; existing-vs-new detected by identity word and expected size.
- Detach via `munmap` (never truncate while peers may be attached); a separate
  explicitly destructive reset path for tests only.
- Explicit error codes from the attach path (no exceptions).
- `shm_attach_test.cpp`: two processes/threads sharing one region; stale or
  wrong-size object rejected.

## Acceptance Criteria

- Attach/detach round-trips against a named region.
- Stale-object rejection on wrong magic/size.
- Gate G1.4 passes (attach tests green, including stale rejection).

## Validation

Gate G1.4 passed (GoogleTest build, `-R shm`; also Catch2 and ASan+UBSan/TSan
matrix parity). Raw output recorded in [`NOTES.md`](../../NOTES.md) (Gate G1.4).

## Completion Notes

Complete. Attach API is `SharedRegionHandle::create_or_open` / `detach` /
`destroy` in `shared-memory/include/safety_crit/shared_memory/shm_attach.hpp`
(`src/shm_attach.cpp`) — deliberately a dedicated header rather than
`shared_region.hpp` (deviation #11 / DEC-0007 #1: keeps POSIX system headers out
of the widely-included layout header). Create-vs-existing detection by object
size + identity; wrong-size => `kSizeMismatch`, bad magic/version =>
`kStaleIdentity`; `MADV_DONTFORK` set; detach never unlinks (test-only
`destroy()` does). No layout change (`kRegionVersion` stays 3). Six tests in
`shm_attach_test.cpp` (lowercase `shm_attach` suite so `ctest -R shm` matches).
This unblocks T-0006 (T1.5).
