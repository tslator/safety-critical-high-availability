# AI Guidance Architecture: Consensus Summary

**Status:** Approved design summary; implementation pending.

## Purpose

Establish `docs/ai-guidance/` as the canonical, central, tool-neutral source of project AI guidance for GitHub Copilot, Abacus, and Tauren/Pi. This document records the agreed architecture and the remaining verification actions.

## Governing Principle

`docs/ai-guidance/` is the **only authored and authoritative guidance source**. Root `AGENTS.md` and `.github/copilot-instructions.md` are committed, generated derivatives. They must not be edited by hand.

In this design, “single source of truth” means one authoritative **authored** location. Checked-in generated derivatives are allowed because they are deterministically reproduced from the canonical source and validated in CI.

## Tiered Guidance Model

### Tier 1 — always injected

`docs/ai-guidance/CORE.md` contains a concise, high-criticality core card. It should contain only non-negotiable requirements that every agent must have in context before work begins, such as critical safety invariants, hot-path constraints, and the applicable verification gates.

Requirements for `CORE.md`:

- Keep it deliberately concise and readable by all agents, including local/small models.
- Make each requirement imperative and testable where possible.
- Pair each critical tenet with its relevant CI/test/sanitizer verification gate where known.
- Treat it as the sole source for Tier 1 text embedded in generated adapters.

### Tier 2 — detailed and task-relevant

Tier 2 documents provide complete rationale, detailed requirements, workflows, and architecture-specific context. Generated adapters direct agents to read the entry documents first and then the task-relevant focused documents.

## Generated Adapter Requirements

### Shared requirements

Both `AGENTS.md` and `.github/copilot-instructions.md` must:

1. Be generated by `scripts/sync-agent-guidance.sh`.
2. Include a visible generated-file header identifying `docs/ai-guidance/CORE.md` as their Tier 1 source and warning against manual edits.
3. Embed the current `CORE.md` content.
4. Direct agents to read `README.md` and `PROJECT_GUIDANCE.md` before planning or editing.
5. Include an enumerated list of focused Tier 2 documents for task-dependent reading.
6. State that guidance under `docs/ai-guidance/` is authoritative.

### Destination-specific paths

Use paths that resolve relative to the generated file's location:

| Adapter | Canonical guidance path prefix |
|---|---|
| `AGENTS.md` | `docs/ai-guidance/` |
| `.github/copilot-instructions.md` | `../docs/ai-guidance/` |

The embedded Tier 1 core content remains equivalent in both adapters. Only path references and any necessary destination metadata differ.

## Generator and CI Contract

`scripts/sync-agent-guidance.sh` has two required modes:

- **Default mode:** regenerate and overwrite `AGENTS.md` and `.github/copilot-instructions.md` from the canonical documents and template.
- **Check mode:** `scripts/sync-agent-guidance.sh --check` regenerates expected output without modifying tracked files and exits nonzero when generated output differs from committed adapters.

CI must run the check mode. A pull request that changes `CORE.md`, the adapter template, or relevant generation inputs without committing regenerated adapters must fail.

Provide an optional POSIX pre-commit hook that runs the same check or regeneration workflow locally. The hook is a convenience only; CI is the mandatory enforcement point.

A content hash is not required. Deterministic regeneration and diffing are sufficient validation.

## Explicitly Rejected Approaches

- Hand-maintained copies of Tier 1 tenets in `AGENTS.md` or `.github/copilot-instructions.md`.
- Symlinking `.github/copilot-instructions.md` to `AGENTS.md`.
- Depending on unsupported custom Markdown include/import syntax.
- Making root `AGENTS.md` the canonical authored home for all guidance.
- Creating separate, independently authored guidance for Abacus, Copilot, or Pi.
- Treating prose guidance as a replacement for tests, sanitizers, CI, or other engineering controls.

## Success Criteria

The architecture is successfully implemented when:

- All authored AI guidance resides under `docs/ai-guidance/`.
- `CORE.md` is the single source of embedded Tier 1 adapter content.
- `AGENTS.md` and `.github/copilot-instructions.md` are generated and clearly marked as such.
- Both adapters contain correct destination-relative links to the canonical guidance.
- CI runs `scripts/sync-agent-guidance.sh --check` and rejects adapter drift.
- An optional POSIX pre-commit hook is available.
- Copilot, Abacus, and Tauren/Pi loading behavior has been verified and documented.
- The decision, implementation task, and review archive use the project's assigned identifiers in place of `DEC-NEXT` and `T-NEXT`.
